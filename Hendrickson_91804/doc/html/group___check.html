Detailed Description

Includes functions to test the acceleration and pressure sensors as well as a validity of the Melexis data stored in the nvRAM.

Warning
  • Application has to be in the System mode to call these functions!
  • After both cold and warm bootstraps the part is configured to be in the System mode by default. If the User mode is set by application after the bootstrap, the functions have to be called inside of the SYSTEM_MODE** section managed by the macros ENTER_SECTION and EXIT_SECTION** specified in <atomic.h>.

◆ Check_IsBadAccelX()

bool Check_IsBadAccelX ( int16_t  min_threshold,
int16_t  max_threshold 
)

implements the X-axis acceleration sensor diagnostic using the internal hardware that allows applying an electrostatic stimulus moving the sensor's rotor and hence simulating a real acceleration.

The resultant displacement is measured as a virtual acceleration. By applying thresholds to the measured values it is possible to detect both mechanical and electrical damages of the acceleration sensors.

Parameters
min_thresholdis a minimal threshold acceptable for the static acceleration test.
max_thresholdis a maximal threshold acceptable for the static acceleration test.
Returns
true if X-axis acceleration sensor failed, and false if the sensor is Ok.
Precondition
Because the function Check_IsBadAccelX() reads some calibration data directly from the nvRAM, after each wake up and before calling the function the nvRAM has to be recalled by the library function NvRam_Recall().
Note
  • The measurements are done with PGA gain increased twice. It can saturate a signal at high acceleration within its specified input range.
  • The implemented approach is sensitive to the acceleration change that is unavoidable during a driving. That is why and because of the reason above, it is strictly recommend using the function Check_IsBadAccelX at the stationary / parking conditions only.
  • Any measurement error happened at diagnostic can be detected by invoking the function Adc_IsError().
  • Make sure a correct profile is used to build an application. The profile has to match the device type. The function Check_IsBadAccelX() returns a correct data only for devices having the X-axis acceleration sensor.

◆ Check_IsBadMlxData()

DataCheck_Type Check_IsBadMlxData ( void  )

verifies integrity of the Melexis calibration and tracking data that is stored in the highest half of the nvRAM.

The verification is based on the ROM BIST 24-bit signature calculation according to the polynomial: x^24 + x^23 + x^22 + x^17

Returns
verification result status including 3 states:
  • nvRAM data is valid;
  • nvRAM data is invalid;
  • ROM BIST calculation failed.

See DataCheck_Type for details.

Precondition
  • Because the function reads the calibration data directly from the nvRAM, it recalls the nvRAM by the library function NvRam_Recall().
  • Application has to be in the System mode to call this function!
  • After both cold and warm bootstraps the part is configured to be in the System mode by default. If the User mode is set by application after the bootstrap, the function has to be called inside of the SYSTEM_MODE** section managed by the macros ENTER_SECTION and EXIT_SECTION** specified in <atomic.h>.

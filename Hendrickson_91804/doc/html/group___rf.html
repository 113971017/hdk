◆ RfTx_Calibrate()

bool RfTx_Calibrate ( void  )

RFTX block calibration: the function finds an optimal value for PLL_VCOREG_TRIM based on current conditions (voltage, temperature, etc.)

Returns
  • true if calibration failed; maximum 5 calibration attempts are performed before reporting the calibration failure.
  • false if calibration is completed successfully.
Precondition
  • Because the function reads the calibration data directly from the nvRAM, after each wake up and before calling the function the nvRAM has to be recalled by the library function NvRam_Recall().
  • Application has to be in the System mode to call this function!
  • After both cold and warm bootstraps the part is configured to be in the System mode by default. If the User mode is set by application after the bootstrap, the function has to be called inside of the SYSTEM_MODE** section managed by the macros ENTER_SECTION and EXIT_SECTION** specified in <atomic.h>.
Warning
  • Calibration enables XTAL oscillator and keeps it enabled to be ready for the following transmission. To be power efficient, RFTX transmission shall be started as soon as possible after the calibration.
  • LF reception is switched off before the calibration and needs to be explicitly enabled after the calibration if needed.
Note
  • For CA devices the function takes about 1 ms plus a start-up time of the XTAL oscillator.
  • The XTAL oscillator start-up time is specified below 1.4 ms with a typical value about 0.7 ms.
  • Before calibration, XTAL oscillator is enabled and mode RFTX_MODE 7 is configured (7: crystal and VCO ON for calibration, VCO and crystal. start simultaneously). After calibration, XTAL oscillator remains active and RFTX_MODE mode remains 7.
  • PLL_FORCE_VCTR port is pre-loaded from nvRAM at boot-time and only enabled for the time of calibration (PLL_EN_FRC_VCTR).

◆ RfTx_Init()

void RfTx_Init ( const RfTxConfig_Type *  cfg)

Initialization of the RFTX block with the next flush of the RFTX FIFO buffer.

Parameters
cfg: A pointer to the RFTx configuration data structure (see RfTxConfig_Type for details).
Precondition
  • It is strongly recommended to assign all values directly in the RFTx configuration data structure. Being not assigned, the value takes on zero.
  • Application has to be in the System mode to call this function!
  • After both cold and warm bootstraps the part is configured to be in the System mode by default. If the User mode is set by application after the bootstrap, the function has to be called inside of the SYSTEM_MODE** section managed by the macros ENTER_SECTION and EXIT_SECTION** specified in <atomic.h>.
Note
  1. The crystal frequency is fixed in the library and has to be 26.0 MHz (RF_XTAL_FREQ_IN_KHZ = 26000).
  2. The parameter **.extra** of the RfTxConfig_Type structure points to the extra RFTX configuration in RfTxExtraConfig_Type that defines:
    • RFTX central frequency divider value (RFTX_CENTER_FREQ_L, RFTX_CENTER_FREQ_H and RFTX_CENTER_FREQ_U);
    • XTAL capacitor configuration (PLL_EN_XTAL_INT_CAP);
    • RFTX mode selection (RfTxPresetId_Type) to specify the RFTX power mode, VPA bypass mode and RFTX frequency range.
  3. If RfTxConfig_Type.extra pointer is not initialized (or initialzed to 0), the default extra configuration is applied:
    • RFTX central frequency is set to 433.92 MHz (RFTX_CENTER_FREQ_IN_KHZ = 433920);
    • Internal capacitance of the nodes XTALP and XTALN is configured with 6pF (PLL_EN_XTAL_INT_CAP_ID = 1);
    • RFTX output power is set to 5 dBm for all library profiles supporting 5 or 9 bar pressure ranges and set to 8 dBm for other library profiles supporting 14 bar pressure range;
    • VPA regulated mode is applied (RF_VPA_BYPASS is disabled).

◆ RfTx_Run()

bool RfTx_Run ( void  )

Implements RF transmission with configuration and payload data prepared in advance.

  • RF transmission is started with the immediate switching to the STOP mode.
  • Both RFTX_DONE wake-up and interrupt are enabled to ensure a proper exit from the STOP mode.
  • Function waits until RF TX is fully finished before the return.
Returns
  • true: when TX failed.
  • false: when TX succeeded.
Precondition
  • Application has to be in the System mode to call this function!
  • After both cold and warm bootstraps the part is configured to be in the System mode by default. If the User mode is set by application after the bootstrap, the function has to be called inside of the SYSTEM_MODE** section managed by the macros ENTER_SECTION and EXIT_SECTION** specified in <atomic.h>.
Warning
  • The function returns a correct error status only with enabled RFTx message handler (when RFTX_DIRECT_MOD = 3).
  • LF reception is switched off before the RF transmission and needs to be explicitly enabled after transmission if needed.
  • It is recommended to disable all wake-up events before the RF transmission because it can move the system from the STOP to HALT mode during the transmission and hence increase a power consumption.
Note
  • Precharge procedure provides optimal conditions to lock PLL.
  • The function uses RFTX_DONE interrupt ISR to exit STOP mode.
  • The function modifies the pending and mask bits of the RFTX_DONE interrupt, while the priority of the RFTX_DONE interrupt is not affected.

◆ RfTx_RunFromBuf()

bool RfTx_RunFromBuf ( const uint8_t  payload_data[],
uint16_t  payload_size 
)

Provides a completed RF transmission of the payload data stored in memory array.

  • RF transmission is started with the immediate switching to the STOP mode.
  • The STOP mode can be interrupted to add data to the FIFO if needed.
  • Both RFTX_HALF wake-up and interrupt are enabled to ensure a proper exit from the STOP modes to feed the FIFO.
  • Both RFTX_DONE wake-up and interrupt are enabled to ensure a proper exit from the last STOP mode.
  • Function waits until RF TX is fully finished before the return.
Parameters
payload_datais a poiter to the array with the payload data.
payload_sizeis a number of the bytes to be taken from the payload_data array to transmit (up to 255 bytes are supported).
Returns
  • true: when RFTx failed.
  • false: when RFTx succeeded.
Precondition
  • Application has to be in the System mode to call this function!
  • After both cold and warm bootstraps the part is configured to be in the System mode by default. If the User mode is set by application after the bootstrap, the function has to be called inside of the SYSTEM_MODE** section managed by the macros ENTER_SECTION and EXIT_SECTION** specified in <atomic.h>.
Warning
  • The function returns a correct error status only with enabled RFTx message handler (when RFTX_DIRECT_MOD = 3).
  • LF reception is switched off before the RF transmission and needs to be explicitly enabled after transmission if needed.
  • It is recommended to disable all wake-up events before the RF transmission because it can move the system from the STOP to HALT mode during the transmission and hence increase a power consumption.
Note
  • Precharge procedure provides optimal conditions to lock PLL.
  • The function uses RFTX_DONE and RFTX_HALF interrupt ISR to exit STOP modes.
  • The function modifies the pending and mask bits of the RFTX_DONE and RFTX_HALF interrupts, while the priority of the interrupts are not affected.

Introduction

This SW library package provides an interface to the following blocks of the TPMS chips ([name] below means a right side of the different functions names):

  • AbsWatchdog_[name]: Absolute Watchdog timer (AWD) Interface, sensorlib.h
  • Accel_[name]: Raw Acceleration measurement conversions, sensorlib.h
  • Accel_[name]: Raw Acceleration measurements with Low Pass HW Filter, sensorlib.h
  • Adc_[name]: Analog-to-digital conversions to get raw Pressure, raw Temperature, etc., sensorlib.h
  • Atomic sections support, atomic.h
  • builtin_[name]: Builtin MLX16 CPU functions, builtin_mlx16.h
  • Calc_[name]: PVT sensors' compensation and memory signature computation, sensorlib.h
  • Check_[name]: Sensors' operability and nvRAM factory data validation, sensorlib.h
  • Diag_[name]: Diagnostic Interface support, diag.h
  • DEBUG_[name]: Debug functions, debug.h
  • Flash_[name]: Flash memory Interface, sensorlib.h
  • Gpio_[name]: General-purpose input/output pins, sensorlib.h
  • I2C_[name]: I2C master functions, i2c_master.h, i2c_master_trx.h
  • Itc_[name]: Interrupt Controller (ITC) Interface, sensorlib.h
  • Lf_[name]: Low Frequency (125 kHz) Transceiver common functions, sensorlib.h
  • LfRx_[name]: Low Frequency (125 kHz) Receiver Interface, sensorlib.h
  • LfTx_[name]: Low Frequency (125 kHz) Transmitter Interface, lftx.h
  • NvRam_[name]: Non-volatile random-access memory (nvRAM) Interface, sensorlib.h
  • Phys_[name]: Acceleration measurement in physical units, sensorlib.h
  • RfTx_[name], Radio_[name]: Radio frequency (300-450 MHz) Transmitter Interface, sensorlib.h
  • SimpleTimer1_[name], SimpleTimer2_[name]: Simple Timers' Interface, sensorlib.h
  • Sys_[name]: System Library Functions, sensorlib.h
  • TempSensor_[name]: Temperature Sensor Interface, sensorlib.h
  • Wakeup_[name]: Wake-up Controler Interface, sensorlib.h
  • WakeupTimer_[name]: Wake-up Timer Interface, sensorlib.h

Library Header files

All header files available in the SW library can be grouped in 3 parts:

  1. Basic header files that declare standard functions and data structures of the C-language. All these files are delivered with the C-compiler package. Examples: <stdint.h>, <stdbool.h>, etc.
  2. Header files related to the Amalthea platform. The files are placed in the library folder ".\platform_amalthea\include". Examples: <atomic.h>, <builtin_mlx16.h>, <delay.h>, <mathlib.h>, <dsp.h>, <compiler_abstraction.h>, <static_assert.h>. All these files are included into a single header file <platformlib.h> to simplify the application code.
  3. Product related header files located in the library folder ".\platform_amalthea\custom\include":
    • <sensorlib.h> : the main product specific header file of the library.
    • <debug.h> : declares the functions and macros that can be used to output debug information.
    • <diag.h> : is responsible for a unique internal hardware that allows to compare analog input signals with programmable thresholds (can be useful for very specific applications only).
    • <lftx.h> : should be added for the special applications requiring the LFTx interface.
    • <i2c_master.h>, <i2c_master_trx.h> : support SW based I2C interface.
    • <deprecated.h> : declares the deprecated functions. It is not recommended to use the deprecated functions in new designs, as they can be removed from the next library releases.
    • <io.h> : supports the low level access to the system registers (see section below for details).

Direct access to the System Registers

If some functionality is missed in the library, it can be still achieved via IO_SET / IO_GET functions from io.h layer. This interface opens a full access to the system registers:

IO_SET(BLOCK, FIELD, value); // write register FIELD of BLOCK
v = IO_GET(BLOCK, FIELD); // read register FIELD of BLOCK

For example, the next two instructions write and read the register MODE belonging to the STIMER2 block:

IO_SET(STIMER2, MODE, 0); // write 0 to register MODE of STIMER2 block
v = IO_GET(STIMER2, MODE); // read register MODE of STIMER2 block

Nevertheless, please note it is strongly recommended to avoid a direct access to the system registers without approval from Melexis. If needed Melexis can extend the list of the supported high level library functions to prevent a direct access to the registers in the final application firmware.

Available Profiles

The library supports chip variants with different pressure ranges (100-500 kPa, 100-900 kPa and 100-1400 kPa) and different acceleration sensing: X-axis and Z-axis with different input ranges, XZ-axes and the option without acceleration sensor (91803 parts). For example, to build the application with the 91804CA_9BAR_X profile, the next line in the Makefile should be used:

PROFILE=91804CA_9BAR_X

The DEFAULT profile is to simplify switching all library examples to any required profile, because all examples' makefiles include the line PROFILE = DEFAULT. By default the DEFAULT profile is an alias for the 91804CA_9BAR_XZ profile. It is not recommended to build an application with the DEFAULT profile.

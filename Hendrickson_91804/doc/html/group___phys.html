Detailed Description

Functions to get sensor values in physical units (currently, implemented for the acceleration).

Warning
  • Application has to be in the System mode to call these functions!
  • After both cold and warm bootstraps the part is configured to be in the System mode by default. If the User mode is set by application after the bootstrap, the functions have to be called inside of the SYSTEM_MODE** section managed by the macros ENTER_SECTION and EXIT_SECTION** specified in <atomic.h>.

◆ Phys_AccelerationX()

int16_t Phys_AccelerationX ( void  )

The function measures a signal coming from the front-end interface of the X-axis acceleration sensor, compensates both offset and sensitivity and converts the obtained value to the physical unit.

Returns
a signed 16-bit value that represents X-axis acceleration component expressed in [g] multiplied by 10. The returned value has to be divided by 10 to get a result expressed in [g].
int16_t accel_in_g = Phys_AccelerationX() / 10;
Precondition
Because the function Phys_AccelerationX() reads some calibration data directly from the nvRAM, after each wake up and before calling the function the nvRAM has to be recalled by the library function NvRam_Recall().
Note
  1. The acceleration sensor front-end circuits are temporarily enabled during the measurement. After the measurement it is disabled to save energy.
  2. To implement the AD-conversion the function Phys_AccelerationX() calls the internal library function declared as "int16_t adc_ll_read_accel(void);".
  3. The function adc_ll_read_accel() executes measurements with 14-bit resolution and normal output range [-8191...8190]. The returned values outside of this range represent an ADC overflow.
  4. To implement an efficient averaging inside of the Phys_AccelerationX() function, an application can override the function adc_ll_read_accel() by executing a single measurement desired times with the next averaging of the resultant data. The single measurement is implemented by the internal library function declared as "int16_t adc_ll_read_accel_once(void);". For the reference see the adc_sens example available in the library.
  5. The averaging above always takes place for both functions Phys_AccelerationX() and Phys_AccelerationZ().
  6. The standard default library option provides no averaging inside of the function Phys_AccelerationX(). In this case the internal function adc_ll_read_accel() calls the function adc_ll_read_accel_once() just once to implement a single measurement.
  7. If the averaging above is needed, it is responsibility of application to implement it. Melexis is responsible only for the standard default option of the function Phys_AccelerationX().
  8. Any error detected during the function execution can be checked by invoking the function Adc_IsError().
